# SecureMailScope Demo PCAP Laboratory

These ten binary PCAP fixtures are generated by repository packet builders for repeatable protocol scenarios. They are controlled lab fixtures, not traffic captured from real organizations or incidents.

Upload a capture through Intake and start its analysis. Findings and evidence are produced by the normal pipeline from observed packets. To establish a drift baseline, analyze three distinct captures with the same profile before the changed capture. A single baseline/downgrade pair does not meet the baseline threshold and does not by itself prove a drift event.

| Capture | Scenario |
| --- | --- |
| `01_secure_smtp.pcap` | SMTP with negotiated TLS 1.3 and visible packet evidence |
| `02_deprecated_tls.pcap` | TLS 1.0 negotiation |
| `03_weak_cipher.pcap` | RC4 cipher negotiation |
| `04_expired_certificate.pcap` | Certificate expired at capture time |
| `05_starttls_rejected.pcap` | Server rejects an advertised STARTTLS attempt |
| `06_truncated_tls.pcap` | Incomplete TLS handshake evidence |
| `07_multi_session_smtp.pcap` | Three SMTP flows in one capture |
| `08_baseline_secure.pcap`, `09_baseline_downgrade.pcap` | Ordered baseline and downgrade pair |
| `10_certificate_rotation.pcap` | Certificate rotation on a stable infrastructure identity |

`manifest.json` keeps scenario expectations separate from observed output from the last generator run. Observations are a reproducibility record, not independent verification or a promise of identical stateful drift results in every environment. For authoritative automated coverage, run `backend/tests/test_phase9_scenarios.py`.
